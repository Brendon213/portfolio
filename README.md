# Портфолио

Одностраничное статическое портфолио на HTML, CSS и небольшом vanilla JavaScript. Страница использует тёмную фиолетовую тему, согласованную с визуальным языком QuantiLoom.

## Запуск

Откройте `index.html` двойным кликом в браузере. Либо из корня проекта запустите:

```bash
python -m http.server 8000
```

После этого откройте `http://localhost:8000`.

## Запуск в Docker (постоянный локальный сервер)

Сайт упакован в образ на базе `nginx:stable-alpine` и запускается через Docker Compose. Внутрь образа попадают только опубликованные файлы (`index.html`, `css/`, `js/`, `assets/`); `doc/` и служебные файлы в образ не включаются.

Запуск или пересборка после правок:

```bash
docker compose up -d --build
```

Проверка состояния и здоровья контейнера:

```bash
docker compose ps        # STATUS должен стать healthy
docker compose logs -f   # логи nginx (Ctrl+C — выход)
```

Локальная проверка: откройте `http://127.0.0.1:8080`. По умолчанию сайт доступен из локальной сети (порт привязан к `0.0.0.0`). Чтобы ограничить доступ только локальной машиной:

```powershell
$env:PORTFOLIO_HOST="127.0.0.1"; docker compose up -d
```

Порт можно переопределить: `$env:PORTFOLIO_PORT=8081; docker compose up -d`.

### Безопасность при публичной доступности

Если сайт запущен с `0.0.0.0`, он доступен на всех сетевых интерфейсах хоста. Убедитесь:

- Брандмауэр Windows настроен корректно (при первом запуске Windows может предложить разрешить доступ — выбирайте «Частная сеть» для доверенных сетей или «Общедоступная», если сайт предназначен для внешних посетителей).
- Если компьютер подключён к корпоративной или публичной Wi-Fi сети, сайт будет доступен участникам этой сети. Для доступа только с одного устройства используйте `PORTFOLIO_HOST=127.0.0.1`.

Остановка и перезапуск:

```bash
docker compose stop      # остановить (контейнер остаётся)
docker compose start     # запустить снова
docker compose restart   # перезапустить
docker compose down      # удалить контейнер (образ останется)
```

Сервис использует `restart: unless-stopped`: Docker сам поднимает контейнер после перезапуска хоста, если вы не останавливали его вручную (`stop`). Для этого нужно, чтобы **Docker Desktop запускался при входе в Windows** (Settings → General → Start Docker Desktop when you sign in) и был запущен.

## Публикация через Tailscale Funnel (отдельный шаг по вашему решению)

Стабильный публичный адрес можно получить бесплатно через Tailscale Funnel: он даёт домен вида `https://<device>.<tailnet>.ts.net` с автоматическим HTTPS, скрывает домашний IP за релеем Tailscale и **не требует проброса портов на роутере**. Funnel работает и с текущей привязкой `0.0.0.0:8080` — скрипт подключается к `127.0.0.1:8080` напрямую.

Подготовка (шаги уровня хоста, требуют вашего явного действия):

1. Установить Tailscale для Windows: <https://tailscale.com/download> (в этой задаче он не устанавливался).
2. Войти в аккаунт (бесплатного плана достаточно): `tailscale up` и вход в браузере.
3. Убедиться, что HTTPS-сертификаты включены (Tailscale предложит при первом `funnel`).

Когда Tailscale установлен и залогинен, а контейнер работает:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\enable-public-funnel.ps1
```

Скрипт проверит CLI и логин, дождётся ответа локального origin на `http://127.0.0.1:8080`, включит Funnel в фоне (`tailscale funnel --bg 8080`) и покажет статус с публичным URL. Отключение публикации: `tailscale funnel off`. Скрипт ничего не устанавливает, не трогает firewall/роутер и не хранит ключи.

### Честные ограничения этого варианта

- Домашний ПК должен быть включён: сон, выключение или сбой питания = сайт недоступен.
- Недоступность интернета у провайдера = сайт недоступен.
- Остановленный Docker Desktop или Tailscale = сайт недоступен.
- Funnel — бета-функция с лимитами трафика; для серьёзной нагрузки она не предназначена.
- Если важен стабильный аптайм, надёжнее бесплатный статический хостинг (например, GitHub Pages / Cloudflare Pages): репозиторий с этими же файлами деплоится без домашнего ПК.

## Публикация на Cloudflare Pages (рекомендуемый вариант)

Статический сайт можно развернуть бесплатно на [Cloudflare Pages](https://pages.cloudflare.com/). Это даёт стабильный публичный URL с HTTPS, не зависит от домашнего ПК, Docker или Tailscale и автоматически пересобирается при каждом пуше в репозиторий.

### Локальная проверка публикации

Скрипт `deploy/publish.sh` (bash/WSL/Linux/macOS) или `deploy/publish.ps1` (PowerShell/Windows) копирует только опубликованные файлы (`index.html`, `css/`, `js/`, `assets/`) в чистую папку `dist/`:

```bash
# bash / WSL / Linux / macOS
bash deploy/publish.sh

# PowerShell (Windows)
powershell -ExecutionPolicy Bypass -File .\deploy\publish.ps1
```

Проверить результат локально. В Windows используйте PowerShell-скрипт из примера выше, а команду `bash` — в WSL, Linux или macOS:

```bash
python -m http.server 8000 --directory dist
```

Откройте `http://localhost:8000` — сайт должен вернуть HTTP 200, CSS/JS/изображения доступны.

### Настройка репозитория на GitHub

1. Создайте новый репозиторий на GitHub (публичный или приватный — Cloudflare подключится в любом случае).
2. Инициализируйте Git и запушьте проект:

```bash
git init
git add .
git commit -m "Initial portfolio"
git remote add origin https://github.com/<ваш-логин>/<repo>.git
git push -u origin main
```

3. Убедитесь, что файлы `index.html`, `css/`, `js/`, `assets/` и `deploy/publish.sh` находятся в корне репозитория.

### Подключение к Cloudflare Pages

Ваши действия (требуют авторизации в аккаунте Cloudflare):

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/).
2. Перейдите в раздел **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
3. Выберите GitHub-аккаунт и авторизуйте доступ к нужному репозиторию.
4. Укажите настройки сборки:
   - **Production branch**: `main`
   - **Build command**: `bash deploy/publish.sh`
   - **Build output directory**: `dist`

Оставьте стандартную Linux-среду сборки Cloudflare Pages: команда публикации использует Bash и обычные Unix-команды копирования файлов.
5. Нажмите **Save and Deploy**.

Cloudflare запустит первую сборку. После завершения сайт будет доступен по адресу `https://<ваш-проект>.pages.dev`.

### Автоматический деплой

После настройки каждый пуш в ветку `main` автоматически запускает сборку и деплой на Cloudflare Pages. Ручной запуск доступен в панели Cloudflare: **Workers & Pages** → ваш проект → **Retry deployment**.

### Дополнительно: пользовательский домен (опционально)

Если у вас есть свой домен:

1. В Cloudflare Dashboard: ваш домен → **DNS** → добавьте CNAME-запись `<поддомен>` → `<проект>.pages.dev`.
2. В настройках проекта Cloudflare Pages: **Custom domains** → **Set up a custom domain** → введите полный домен.
3. HTTPS-сертификат будет выпущен автоматически.

### Ограничения Cloudflare Pages

- Сайт статический — серверная логика не выполняется.
- Скрипт публикации копирует в `dist/` только `index.html`, `css/`, `js/` и `assets/`; файлы `doc/`, `deploy/`, `README.md` и `.gitignore` посетителям не раздаются.
- Лимиты и условия тарифного плана могут меняться; перед запуском коммерческого проекта проверьте актуальные условия Cloudflare.

## Структура

- `index.html` — содержание страницы, контакты и проекты;
- `css/style.css` — токены темы, стили и адаптивная вёрстка;
- `js/main.js` — доступное мобильное меню;
- `assets/icons/favicon.svg` — иконка сайта;
- `assets/images/projects/` — опубликованные оптимизированные изображения проектов;
- `doc/` — исходные скриншоты и CSS-референсы, не подключаемые к странице напрямую;
- `deploy/` — скрипты развёртывания: `publish.sh` / `publish.ps1` (сборка `dist/`), `enable-public-funnel.ps1` (Tailscale Funnel), `nginx.conf`.

## Что редактировать

Имя, роль и краткое описание находятся в блоке `#top` файла `index.html`. Текст раздела «Обо мне» редактируется в `#about`, а карточки проектов — в `#projects`. Контактные ссылки находятся в секции `#contact`: используйте `mailto:` для email, `tel:` для телефона и URL Telegram для мессенджера.

## Изображения проектов

Исходные изображения сохраняются в `doc/`, а сайт использует их оптимизированные WebP-копии:

- `doc/TelegramBotScreen1.png` → `assets/images/projects/project-1/cover.webp`;
- `doc/TelegramBotScreen2.png` → `assets/images/projects/project-1/screen-1.webp`;
- `doc/QuantiLoomScreen1.png` → `assets/images/projects/project-2/cover.webp`.

Для новых изображений положите готовый WebP в папку нужного проекта и добавьте `<img>` в соответствующую карточку с точными `alt`, `width`, `height`, `loading="lazy"` и `decoding="async"`. Не заменяйте и не удаляйте исходники из `doc/`: это архив для повторной подготовки ассетов.

## Как добавить проект или изображение

1. Скопируйте одну из карточек `<article class="project-card">` в секции `#projects`.
2. Обновите название, описание, возможности и стек только подтверждёнными фактами.
3. Создайте папку `assets/images/projects/project-3/`, добавьте туда оптимизированные WebP-файлы и укажите их в карточке.
4. Добавьте честные `alt`-тексты и размеры изображений, затем проверьте страницу в мобильной ширине.
